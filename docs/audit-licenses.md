# OSS License Audit

Migrated from WM-953, this audit was requested by the public-release plan (WM-804) as
a precondition for flipping repository visibility: it establishes that Factory's
dependency tree, vendored code, and shipped media assets are compatible with the
project's own Apache-2.0 license ([WM-791](../LICENSE)).

- **Date:** 2026-08-22
- **Scope:** direct + transitive dependencies of `package.json` (repo root) and
  `event-runtime/web/package.json`, per this ticket's Acceptance Criteria. Vendored
  source and shipped media/font assets across the whole tree were reviewed manually
  (see [Vendored source](#vendored-source-and-redistribution-rights) and
  [Media and font assets](#media-and-font-assets) below).
- **Tools:** `license-checker@25.0.1` (via `bunx`) against each package tree's
  `node_modules`, `bun@1.3.14`.
- **Result:** no blocking exceptions. All dependency licenses are Apache-2.0
  compatible; see [Compatibility matrix](#compatibility-matrix).

## Method

For each of the two `package.json` roots in scope:

```bash
bunx license-checker --json --production=false
```

run from that package's directory (so it walks that tree's installed
`node_modules`, direct + transitive). `license-checker` reads the `license`/
`licenses` field (or the `LICENSE`/`LICENSE.md` file when the field is absent) from
each installed package's own `package.json`/manifest and reports `UNKNOWN` when
neither is present — this is what gives the audit its "fail on missing metadata"
property (see [Negative-case handling](#negative-case-handling)) without needing a
bespoke script in this repo. Output was grouped by license below; packages with
copyleft license terms (GPL/AGPL/LGPL/MPL/CDDL/EPL/CPL/SSPL, case-insensitive) were
extracted for individual review.

## Negative-case handling

`license-checker` reports a package's license as `UNKNOWN` when neither a
`license`/`licenses` field nor a discoverable `LICENSE` file is present, rather than
omitting the package or defaulting to a permissive assumption — so a missing license
field surfaces as a visible `UNKNOWN` row in the tool's output instead of passing
silently. Both scans below returned **zero** `UNKNOWN` entries.

## Vendored source and redistribution rights

`extensions/buzz/vendor/` bundles pre-built copies of `@noble/curves`,
`@noble/hashes`, `@noble/ciphers`, and `@scure/base` (Paul Miller / "noble"
project), so the Buzz extension stays self-contained without the factory root's
`bun install` seeing a second `package.json` (see
`extensions/buzz/vendor/README.md`). Each vendored subdirectory (`base/`,
`ciphers/`, `curves/`, `hashes/`) carries its own upstream `LICENSE` file — all
MIT, permissive and Apache-2.0 compatible, and each already satisfies MIT's
"include the license and copyright notice" term by shipping the `LICENSE` file
alongside the code. Attribution was additionally rolled up into `NOTICE` for a
single point of reference. No other `vendor/`, `third_party/`, or copied-source
directories exist in the tree.

`extensions/buzz/package.json`, `demo/repo/package.json`, and
`templates/starter/package.json` were out of this ticket's Acceptance-Criteria
scope (root + `event-runtime/web` only). They were spot-checked while walking
the tree: `extensions/buzz`'s only runtime dependencies are the noble packages
vendored above (already reviewed); `demo/repo` and `templates/starter` declare no
external dependencies of their own. No further action needed.
